# _Stroom Generated Rules Demo_ Content Pack

## Overview
This **Stroom Generated Rules Demo** content pack provides a collection of analytic rules designed to detect suspicious
activity within XML-based Windows Event Logs. It serves as a demonstration of how this automated detection pipeline will 
function when all rules have been implemented.

This pack includes 30 analytic rules, showcasing the system's detection capabilities across a range of security
scenarios.

The rules are derived from industry-recognised sources, including:
- The MITRE ATT&CK framework.
- The Sigma rule set.

Each analytic rule's description references to the original MITRE ATT&CK techniques and Sigma rules, along with
additional metadata such as the original Sigma rule author.

<hr>

## Data Generators
To support testing and demonstration, the content pack also includes 30 data generators, each corresponding to an 
analytic rule.

Once scheduled, each data generator will periodically send an example Windows Event Log into a feed that will trigger 
one of the rules. This allows users to verify the functionality of the rules without the need for external data sources.

<hr>

## Contents
This content pack includes:
- 30 analytic rules.
- 30 data generators (one per rule).
- Output feeds for detections and errors.
- Supporting components for the detection pipeline including:
  - XSLTs
  - Indexes
  - Views
  - Other configuration elements

<hr>

## Feeds
The following feeds are configured within this content pack:
1. **RULE_FEED**
   - Input feed for analytic rules.
   - Receives data from data generators or manual user input.
2. **RULE_OUTPUT_FEED**
   - Receives detection results generated by analytic rules.
3. **RULE_ERRORS_FEED**
    - Captures any errors encountered during rule processing.

<hr>

## Usage
To get started:
1. Add processors to each rule:
   - Open a rule.
   - Navigate to its _Execution_ tab.
   - Add a processor with _Feed is RULE_FEED_ and _Type = Events_.
2. Add execution schedules to each data generator:
   - Open a data generator.
   - Navigate to its _Execution_ tab.
   - Add an execution schedule.
3. Monitor RULE_OUTPUT_FEED for detections.
4. Optionally, manually upload XML logs to RULE_FEED by:
   - Copying the log contained in the template field of the data generator.
   - Save the log in an xml file on your local device.
   - Upload the saved log to RULE_FEED.
